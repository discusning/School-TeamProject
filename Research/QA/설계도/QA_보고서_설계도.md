# 프로토콜 게임 QA 보고서 설계도

새 프로토타입이 나오면 이 설계도로 **보고서 1개 + 안내서 1개**를 만든다.

| 파일 | 들어가는 것 | 쪽 |
| --- | --- | --- |
| 보고서 | 적는 칸만 (테스트 정보, 결과 요약, 해 볼 것, 이상했던 것, 느낀 점) | 2 |
| 안내서 | 적는 법만 (테스트 목적, 쓰는 순서, 칸마다 적는 것, 정도 기준, 파일 이름) | 1 |

## 파일 이름 규칙

| 무엇 | 이름 | 예 |
| --- | --- | --- |
| 버전 | 게임 폴더 끝 숫자 (YYMMDD) | `261108` |
| 같은 날 두 번째 빌드 | 버전 뒤에 `-2` | `261108-2` |
| 빈 보고서 | `프로토콜_QA_보고서_{버전}.pdf` | `프로토콜_QA_보고서_261108.pdf` |
| 안내서 | `프로토콜_QA_안내서_{버전}.pdf` | `프로토콜_QA_안내서_261108.pdf` |
| 후배가 낸 보고서 | `QA_{버전}_{이름}.pdf` | `QA_261108_윤신재.pdf` |
| 후배가 찍은 사진 | `QA_{버전}_{이름}_{번호}.png` | `QA_261108_윤신재_1.png` |

## 폴더

```
바탕화면/서울 생존 구역 보고서/QA_보고서/{버전}/   ← 버전마다 폴더 1개 (규칙)
├─ 1_보고서/       프로토콜_QA_보고서_{버전}.pdf  ← 후배에게 보냄
├─ 2_안내서/       프로토콜_QA_안내서_{버전}.pdf  ← 후배에게 보냄
└─ 3_받은 보고서/  QA_{버전}_{이름}.pdf, 사진     ← 후배가 낸 것

저장소 Research/QA/
├─ 설계도/        ← 틀과 버전 파일
└─ {버전}/        ← 만들어진 PDF 2개
```

## 새 버전 만드는 순서

1. `versions/` 안의 직전 버전 파일을 복사해 `{새 버전}.js`로 저장한다.
2. 아래 "버전마다 바꾸는 곳"만 고친다.
3. `bash make_qa.sh {새 버전}` 을 실행한다.

## 버전마다 바꾸는 곳 (`versions/{버전}.js`)

| 칸 | 어디에 나오나 | 기준 |
| --- | --- | --- |
| `version` | 둘 다 | 폴더 끝 숫자와 같게 |
| `goals` | 안내서 "이번 테스트 목적" | 2~4줄. 이번 버전에서 새로 생긴·고친 기능 위주 |
| `checks` | 보고서 "해 볼 것" | 부분별 묶음, 모두 8~12개. 한 줄에 행동 하나 |
| `bugExample` | 안내서 "칸마다 적는 것"의 예 | 이번 버전 기능으로 된 예시 |
| `bugRows` | 보고서 "이상했던 것" 빈 줄 수 | 기본 9 |

## 고정된 곳 (고치지 않음)

| 파일 | 내용 |
| --- | --- |
| `qa_report.html` | 보고서 틀 |
| `qa_guide.html` | 안내서 틀 (쓰는 순서, 정도 3단계: 심각·보통·가벼움) |
| `qa_style.css` | 두 파일 공통 모양 |

## 작성 규칙

- 보고서에는 설명을 넣지 않는다. 설명은 모두 안내서에.
- 쉬운 말만. 한 줄에 한 가지. 단문.
- 쪽마다 여백이 고르게. "해 볼 것" 줄 높이는 항목 수에 맞춰 자동으로 바뀐다.
- 안내서는 1쪽을 넘기지 않는다.
