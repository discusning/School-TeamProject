# 프로토콜 게임 QA 보고서 설계도

새 프로토타입이 나오면 이 설계도로 QA 보고서 빈 양식을 만든다.

## 파일 이름 규칙

| 무엇 | 이름 | 예 |
| --- | --- | --- |
| 버전 | 게임 폴더 끝 숫자 (YYMMDD) | `261108` |
| 같은 날 두 번째 빌드 | 버전 뒤에 `-2` | `261108-2` |
| 빈 양식 | `프로토콜_QA_보고서_{버전}.pdf` | `프로토콜_QA_보고서_261108.pdf` |
| 후배가 낸 보고서 | `QA_{버전}_{이름}.pdf` | `QA_261108_윤신재.pdf` |
| 후배가 찍은 사진 | `QA_{버전}_{이름}_{번호}.png` | `QA_261108_윤신재_1.png` |

## 받는 폴더

```
바탕화면/서울 생존 구역 보고서/QA_보고서/
└─ {버전}/
   ├─ 프로토콜_QA_보고서_{버전}.pdf   ← 후배에게 보내는 빈 양식
   └─ 받은 보고서/                      ← 후배가 낸 보고서와 사진
```

## 새 버전 양식 만드는 순서

1. `versions/` 안의 직전 버전 파일을 복사해 `{새 버전}.js`로 저장한다.
2. 아래 "버전마다 바꾸는 곳"만 고친다.
3. `bash make_qa.sh {새 버전}` 을 실행한다.
4. PDF가 `Research/QA/`와 바탕화면 `QA_보고서/{새 버전}/`에 생긴다.

## 버전마다 바꾸는 곳 (`versions/{버전}.js`)

| 칸 | 내용 | 기준 |
| --- | --- | --- |
| `version` | 버전 숫자 | 폴더 끝 숫자와 같게 |
| `goals` | 이번 테스트 목적 | 2~4줄. 이번 버전에서 새로 생긴·고친 기능 위주 |
| `checks` | 해 볼 것 (부분별 묶음) | 모두 합쳐 8~12개. 한 줄에 행동 하나 |
| `bugExample` | 3쪽 회색 예시 줄 | 이번 버전 기능으로 된 예시 |
| `bugRows` | 빈 줄 수 | 기본 8 |

## 고정된 곳 (`qa_template.html`, 고치지 않음)

| 쪽 | 고정 내용 |
| --- | --- |
| 1쪽 | 테스트 정보, 쓰는 순서 5단계, 결과 요약 |
| 2쪽 | 해 볼 것 표 모양, 이상한 정도 3단계 (심각·보통·가벼움) |
| 3쪽 | 이상했던 것 표 (정도·언제·내가 한 것·생긴 일·원래 나와야 할 것·또 되나·사진), 느낀 점 3칸 |

## 작성 규칙

- 쉬운 말만 쓴다. "빌드", "재현" 같은 말 대신 "게임 버전", "또 되나".
- 한 줄에 한 가지. 단문.
- 쪽마다 여백이 너무 많거나 적지 않게. "해 볼 것" 줄 높이는 항목 수에 맞춰 자동으로 바뀐다.
