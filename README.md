# 프로토콜: 서울 생존 구역

> 팀명: 미정 — 정해지면 여기에 반영

## 프로젝트 목표

2050년, 외부인 침략 이후의 서울 요새가 무대인 2D 싱글플레이 게임입니다.
플레이어는 요새 입성 심사관이 되어 서류를 대조하고, 사람으로 변장한 외부인을 가려냅니다.
선택에 따라 스토리 루트가 갈리고, 여러 엔딩으로 이어집니다.

- 핵심 시스템: 입성 심사(서류–주민 DB 대조), 외부인 판별, 선택지 분기·멀티 엔딩
- 참고 게임: <페이퍼 플리즈>, <That's My Neighbor Not>
- 개발 범위 기준: [게임팀플_개발범위_가이드.pdf](MeetingMinutes/게임팀플_개발범위_가이드.pdf)

## 개발 환경

## 프로토타입 (검문 파트)

설계 근거: `Research/참고게임_분석_및_프로토타입_설계_보고서_261106` 7~9장.

**실행:** `Assets/_Project/Scenes/Checkpoint.unity` 열고 Play. (장면이 없으면 메뉴 `Protocol Seoul > Setup Project`)

**조작**

| 입력 | 하는 일 |
| --- | --- |
| 서류 탭 클릭 | 임시 통행증 / 검역 소견서 전환 (영수증은 기준 정해진 뒤) |
| `Space` 또는 [검사 모드] | 검사 모드 켜기 → 서류 칸 하나, DB 칸 하나 클릭 → 일치 / 불일치 / 관련 없음 |
| 부스 얼굴 ↔ DB 사진 | 검사 모드에서 비교하면 외부인(얼굴 다름)을 찾을 수 있음 |
| [통과] / [거부] | 판정 → 정답·오답과 이유 표시 → [다음 방문자] |

**들어간 것 (필수 메커니즘 4개)**

| 단계 | 내용 |
| --- | --- |
| P0 | 주민등록 DB 60명 생성, 방문자 생성(오류 하나 심기), 정답 계산 — 자동 테스트 9개 |
| P1 | 검문 루프: 방문자 → 서류 → 통과·거부 → 맞음·틀림 |
| P2 | 서류–DB 대조 (검사 모드) |
| P3 | 외부인 판별 (눈 위치·목 길이 다름), 검역 소견서 (검사일 3일 이내) |
| P4 | 하루 정산 (배급·벌점 임시 숫자), 1~3일차 규칙이 하루씩 늘어남 |

**기획이 숫자 바꾸는 곳:** `Assets/_Project/Resources/Days/Day1~3.asset` — 방문자 수, 오류 확률, 켜진 규칙, 오늘의 지시 문구. 코드 수정 없이 Inspector에서 바꾸면 됨.

**폴더** (`ProtocolSeoul/Assets/_Project/` 아래)

| 경로 | 내용 |
| --- | --- |
| `Scripts/Core/` | 규칙·데이터 (화면 없음). 판정 기준은 `Rules.cs` 한 곳 |
| `Scripts/Game/` | 화면 (임시 UI A안 "부스+책상"), 임시 얼굴 그림, 임시 효과음 |
| `Scripts/Editor/` | 장면·하루 설정 만들기, Windows 빌드 (메뉴 `Protocol Seoul`) |
| `Tests/EditMode/` | 규칙 자동 테스트 (Window > General > Test Runner) |
| `Resources/Fonts/` | Noto Sans KR (SIL OFL 1.1, 라이선스 동봉) |

**임시인 것 (팀 결정 뒤 교체):** 그림 전부(도형), 효과음(코드로 만든 소리), 배급·벌점 숫자, 신고 버튼(비활성), 영수증 탭, 시간 제한 없음.
